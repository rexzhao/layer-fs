## P3-1：`fs-windows`（无 FFI、跨平台、L1）

十个模块：`path` / `case` / `error` / `disposition` / `share` / `delete` / `dirent` / `time` / `length` / `attrs` / `volume`
（+ `no_wildcards` 扫描），**57 例**。每模块**表驱动 + 缺格即红 + 坐标化断言**（失败消息指认格子/规则/输入）。

### 三个机制值得留档

1. **`error` 的穷举由“源码扫描 + 阴性/阳性对照”守**：Rust 无法断言“这个 match 没有通配臂”，所以用自指扫描；
   首版 needle 多一个空格（`"_  =>"`）**永不命中**，阳性对照又用 needle 自己拼文本（同义反复）——两次都“绿着”，被 QA 变异抓出；
2. **`disposition` 删一行是编译错误而非测试红**：`TABLE` 是 `[(Disposition, Exists, Outcome); 18]`，类型化数组长度先于测试报错。
   “缺格即红”的信号强度因此分两级：编译期 > 运行期；
3. **`share` 的 4096 格用独立 oracle 算期望**（不从实现取答案），所以“把 `new_desired & !existing_share` 写成 `!existing_desired`”
   这类语义错误才会红且带坐标。

### QA 的变异结论（12 模块）

| 红得对 | 红但不算数 | 绿了 |
| --- | --- | --- |
| **18** | **0** | **1**（`time` 的“1601 前拒绝”：`i64` 纳秒到不了 1601，公开 API **不可达**，不是缺陷） |

**4 个曾经的“绿了”都是同一类：政策值没进期望值**（折叠规则、句柄方向、纪元常量、扫描 token）。补法不是“再加一张表”，
而是“给政策值写一条**字面量期望**”。

## 本卡沉淀进流程的五条

1. **判据影响行**（提交说明首行）：`无（不改判据）` / `无（澄清：…）` / `改变 <卡/测试名>：<原→新>`；**翻转绿红即停卡**；
2. **“可复现/稳定/确定性”类声明必须先跑两次**，不一致就改声明而不是改测量；
3. **扫描器/探针必须带阳性 + 阴性两个字面量对照**（否则检查器自己会“绿着”）；
4. **替换式注入必须先断言确实改到**（本轮出现过“提交说明写了断言、补丁没落地”）；
5. **测试的前置条件也要断言**（内容寻址下“同字节即同对象”，构造“两个对象”必须 `assert_ne!` 它们的 oid）。
