# 判据与验收纪律（P3 阶段积累；2026-10-26 起生效）

> 来源：P3-2 G1 期间（P3-1/2 的经验 + 本轮 107 条待办）整理。每条一句话 + 出处。
> 分八节：一 判据说的是什么、二 判据的形状、三 计数型判据、四 白名单与豁免、五 变异与对照、六 取证与报告、七 文档与引用、八 review 固定动作。

## 一、判据说的是什么

1. **可证伪性**：每条判据能说出"谁会让它红"。说不出 = 不是判据。
2. **期望独立**：期望值不来自被测物、不两端常量（`assert_eq!(4+4+8+32, 48)` 这类恒真式删掉或改成从实测派生）。
3. **宿主无关**：`cargo test` 的 passed 数会被 `cfg` 门控、`ignored`、feature 筛选；只有**源码扫描**与**字面量基数**是宿主无关的。
   （出处：`#[cfg(windows)]` 门控测试在本机 58 passed、Linux 57 passed 全绿。）
4. **每个数要么可解释、要么被钉住**：`18 = 6×3`（读者能算）/ `57`（不可解释但被字面量钉住）。
   把 57 当可解释 ⇒ 报告含糊；把 18 当被钉住 ⇒ 改动退化成"改数字让它过"。

## 二、判据的形状

5. **按形状查，不按名字查**：改名副本是 grep 的盲区。锚在类型签名/变体名/语法形态，不锚标识符名字。
6. **grep 分不清"引用"与"定义"**：判据锚在定义语法（`pub const TABLE` / `enum X` / `pub use … X`）；引用靠限定前缀区分
   （`Disposition::Supersede` 不算副本，裸 `Supersede` 才算）。
7. **循环计数器 ≠ 基数断言**：`cells == 18` 数的是循环跑了几次；表多一行/重复一行不红。要 `TABLE.len()` / `rows` / `columns` 各自命名。
8. **恒绿判据比没有更糟**：它给出"已验证"的错觉。（例：并发负对照"必须出现两个成功"——`bind` 前置检查使该形态不可达。）

## 三、计数型判据

9. **计数不是目标**：不得为凑数合并/拆分使用点；排除注释与非代码行；每个计数给出它的绕过样例。
10. **同一语义的两个检查若能被不同写法绕过，就都要跑**（`let tail = 48u64` / `0x30` / `n = 48` / `4+4+8+32`）。
11. **数字要带命令**：没有命令的数字，读者只能信或不信。同一量两种口径都可以对，但**不可相加**（如 128 + 76 ≠ 224）。

## 四、白名单与豁免

12. **白名单 = 知识的重复记录**：每加一条就是把一处常量再手写一遍；第 2 条出现时，正确动作是**消灭这份知识**，不是继续登记。
13. **条目数 == 命中数（双向）**：多一条=未登记例外，少一条=腐化（登记的已不存在）。
14. **豁免类规则要能自证**：把豁免对象放进去必须仍绿（例：错引用放进「修订记录」节 ⇒ PASS）。
15. **例外要就近、带理由、可被下一个人读到**（白名单写在判定式旁边，每条形如 `路径:行` + 一句为什么）。

## 五、变异与对照

16. **变异一次一改**，在干净树上做；还原后 `git diff --stat` 必须为空。
17. **对照必须绕过被测函数**：仍调用被测函数的"对照"只证明"这个函数和它自己一致"。
18. **负对照是"把一个不存在的路径造出来"**，不是"反面的用例"——它是故意错的第二套实现。
19. **改判据三件事**：① 干净树绿 ② 植入目标红 ③ 植入良性近似物仍绿。缺任何一件，"改判据"既可能修对，也可能改瞎。
   **误报会被人看见，漏报不会。**
20. **对照的期望值写下来之前先跑一次**：期望从"这条判据要抓什么"推出；写错了会**驱动错误的实现**（去改产品让绿出现）。
21. **一条变异"无法表达" ⇒ 当前实现即为变异态**。这时不要写"无法变异"，要写"当前实现即为变异"。
22. **缺口写成四步**：能力 → 调用 → 断言 → 变异，每步单独可验收（"还没做"看不出缺在第几步）。

## 六、取证与报告

23. **取证四档**：`[grep]` / `[run]` / `[read]` / `[time]`。**"grep 得到 0"与"读代码确认没有"给出同一种结论，但证据强度不同。**
24. **`[read]` 条目写成"我读了 `X:Y`，判断 Z，理由 W"**，不写"已确认无误"（后者把不可复现的判断伪装成可复现的结论）。
25. **报告末行写 `依赖判断的结论：N / M`**；N/M > 0.5 时逐条列出，且 manager 必须自己读一遍再合入。
26. **`[time]` 四件**：阈值 / 实测值 / 机器 / **这条证据支持哪个结论**。只证"曾经阻塞"，不证"永远阻塞多久"。
27. **读法污染**：`[read]` 结论用的是同一种读法；一条被推翻 ⇒ 其余结论重看，**不得只改那一行**。错误不在结论里，在读法里。
28. **三态**：只跑过几次都绿 = 未验证；记录了失败名 = 待环境（附复现命令）；复现并定位 = 缺陷。"再跑 N 次都过"**不升级状态**。
29. **候选（未证实）**：让后来的测量可以替换它，而不必反驳我。修掉一个候选 ≠ 问题不存在。
30. **一条 `[time]` 挂不到任何结论上 ⇒ 不是判据，只是观测记录**（删掉或降级为背景数据）。

## 七、文档与引用

31. **引用记号**：小节 `§X.Y`（必须存在同名标题）；节内条目 `§X 第 Y 条`。
32. **裸 `§X` 只在"上下文明确是本文档"时用**；跨文档或易混处写 `§X 的<名词>`。
33. **ADR 引用与 backlog 条目必须同批**，两个方向都查（ADR 说"留 backlog" ⇒ 条目在哪；backlog 引用 ADR 小节 ⇒ 小节存在）。
34. **改号类动作的守恒判据**：引用总数必须不变（变了 = 有人顺带增删引用）；另查"旧号独有节号"引用数 == 0。
35. **证据必须是某个 ref**：报告/清单里每条“某文件某行是 X”都必须能用 `git show <sha>:<path>` 复现。
   **工作树只能用来运行（测试、变异），不能用来引用**——工作树内容 ≠ 某个 SHA 的内容，而“文件:行”隐含承诺了后者。
   若必须引用未提交状态，写成「**未提交观察**」，不计入结论。
36. **坏引用要坏得能被发现**：行号会过期，但过期时是"点不到"而不是"点到了别处"——后者静默。
36. **失败实验记成"别再这样做"**，不记成"做过且没问题"。
37. **注释与代码不一致是错误信息**，不是风格问题；**替缺陷辩护的注释**更糟——它把 bug 写成了分工。
38. **因果词必须指出测量**（because / so / 导致 / 因此 / deletes）；没有测量的因果一律改写成陈述观察或明标**假设**。

## 八、review 固定动作（按对象问）

| 对象 | 问 | 理由 |
| --- | --- | --- |
| 判据 | 对照跑过吗？**红过吗**？ | 绿只证明它不碍事 |
| 注释 | 它解释的机制**现在还成立吗**？ | 不成立的注释是错误信息 |
| 提交说明的"断言了 X" | **指给我看那一行** | 声称与代码不符已出现多次 |
| 报告里的数字 | 它**可解释**还是**被钉住**？ | 混用会让改动变成"改数字让它过" |
| 缺口 | 缺在**四步中的哪一步**？ | "还没做"看不出缺在哪 |
| control / 对照字样 | 去代码里找**它到底做了什么** | 不看它红没红，看形状有没有实现 |

39. **触碰进程级测试状态的用例必须持守卫** `let _guard = cas_store::testing::serialised();`（函数第一行）。
   **`let _ = ...` 是丢弃模式**（求值后立刻 drop）；`--test-threads=1` 不是解药（顺序污染仍在）。
40. **扫描器三件**：排除自己（并写明"唯一排除"）/ 阳性对照 / 阴性对照；**锚点也要对照**（`find` 失败是 panic = 红了但不算数；
   CRLF 检出下按 `\n` 切会截到文件尾）。

### 附：合并报告要写的三句

- **形状**：一个事务、决定在内（结构性判据，可红）；
- **机制**：写锁覆盖整个闭包（锁探针，`[time]` 档，支持"本层无可观测并发窗口"而非"原子性已通过"）；
- **行为**：SQLite 出错回滚**未由 CI 证明**（人工变异）——把"知道但没证明"写在明面上。

## 九、时间型判据（P3-2 G1 期间三次失败换来的）

41. **只断言下界**：`waited >= X` 与负载无关；`abs_diff(a,b) <= X` 负载一高就红。
42. **靠“某段开销有界”才成立的边界都不是不变量**——不管余量写成常数（`±100`）、写成另一个量（`+measured`）、
   还是写成固定余量（`policy + 1000`）。三者同源：都在假设**前置物化有界**，而它随输入无界（16 MB payload 实测红）。
43. **红了会不会抓错人**：注释管“这句话对不对”，上界管“**红了会不会指控错对象**”。16 MB 那条红会让读者去查等待逻辑，
   真相是钟的起点 ⇒ 不可归因且指控方向错的红，是最该消灭的一类。
44. **`[time]` 档报告四件**：阈值 / 实测值 / 机器 / **这条证据支持哪个结论**；只证“曾经阻塞”，不证“永远阻塞多久”。
    **挂不到任何结论上的 `[time]` 不是判据**，只是观测记录。
45. **可证伪性取决于“能不能只动被测的量而不动期望”**：`HOLD/2` 与 `HOLD` + `MIN_WAIT` 正常运行时完全等价，
   差别只在有人要证伪它时。所以注释该记录“**这个判据是怎么被证伪过的**”，而不只是“它在测什么”。

## 十、计数与分类的口径

46. **数字要带命令**；同一量两种口径都正确但**不可相加**（`128 + 76 ≠ 224`）。
47. **派生分类的计数必须绑定“在哪个提交/口径上数的”**（ADR-005 引用分类 51→72 是因为修复移动了分类，不是新发现 21 条）。
48. **判据数按“独立的失败面”数，不按断言语句数**（同一测试覆盖两条 ⇒ 记 1 条并注明）。
49. **基数的意义在于“为什么是这个数”**；解释不了的数不能当锚（`36 = 18×2` 那次）。

## 十一、证据与引用

50. **证据必须是某个 ref**：`git show <sha>:<path>`；**工作树只能用来运行（测试、变异），不能用来引用**。
   必须引用未提交状态时写「**未提交观察**」，**不计入结论**，且必须**当轮消耗**（下一次提交到达即核）。
51. **未提交观察不得把“缺两件”变成“快好了”**：状态词仍是“缺”，直到提交到达。
52. **坏引用要坏得能被发现**：行号过期是“点不到”而不是“点到了别处”。
53. **引用记号**：小节 `§X.Y`（须存在同名标题）/ 节内条目 `§X 第 Y 条` / 裸 `§X` 只在“上下文明确是本文档”时用。
54. **ADR 引用与 backlog 条目同批，两个方向都查**；新增 B 编号前先搜 ADR 有无引用。
55. **改号类动作的守恒判据**：引用总数必须不变；另查“旧号独有节号”引用数为 0。

## 十二、工具与陷阱

56. **grep 是行级的**：对多行宏（`assert_eq!(` / `assert!(` / `matches!(`）取内容一律用 `-A2`/`-A3`；
   同一行模式跨行必然恒 0（假红），会让人去补一条**已经存在**的东西。
57. **自查单本身也要能红、能绿**：永远 0 或永远 >0 的自查项是假判据。
58. **扫描器三件**：排除自己（写明“唯一排除”）/ 阳性对照 / 阴性对照；**锚点也要对照**（`find` 失败是 panic = 红了但不算数；
   CRLF 检出下按 `
` 切会截到文件尾）。
59. **解析层也要有对照**：一个键可能对应多个对象时（`ADR-005` 两份文件）必须**枚举全部候选再判断**，不得取第一个。
60. **守卫必须绑到有名字的变量**：`let _ = expr;` 的 `_` 是丢弃模式（立即 drop）；`let _guard = …` 才活到作用域结束。
61. **触碰进程级测试状态（`PACK_READ_BYTES` / `SWEEP_ONCE`）的用例，第一行必须持 `testing::serialised()`**；
   `--test-threads=1` **不是**解药（顺序污染仍在）。

## 十三、注释与叙述

62. **注释与代码不一致是错误信息**，不是风格问题；**替缺陷辩护的注释**更糟——它把 bug 写成了分工。
63. **因果词必须指出测量**（`because` / `so` / `导致` / `因此` / `deletes`）；没有测量的因果一律改写成陈述观察或明标**假设**。
64. **改注释也可以有机械证据**（`git grep '<旧措辞>'` = 0），否则下次 review 又要读全文确认。
65. **失败实验记成“别再这样做”**，不记成“做过且没问题”。
66. **“候选（未证实）”**：让后来的测量可以替换它，而不必反驳我；修掉一个候选 ≠ 问题不存在。

## 十五、取证四档（报告用）

71. `[grep]` / `[run]` / `[read]` / `[time]` 四档；**“grep 得到 0”与“读代码确认没有”给出同一种结论，但证据强度不同**。
72. `[read]` 条目写成“我读了 `X:Y`，判断 Z，理由 W”，并给**推翻条件**（能被一次机械检查推翻）；
    写“已确认无误”是把不可复现的判断伪装成可复现的结论。
73. 报告末行：`依赖判断（不可机械复现）的结论：N / M`；**N/M > 0.5 时逐条列出，且 manager 必须自己读一遍再合入**。
74. **读法污染**：一条 `[read]` 被推翻 ⇒ 同一读法的其余结论**必须重看**，不得只改那一行（错误不在结论里，在读法里）。
75. **三态**：只跑过几次都绿 = 未验证；记录了失败名 = 待环境（附复现命令）；复现并定位 = 缺陷。
    **“再跑 N 次都过”不升级状态**。
