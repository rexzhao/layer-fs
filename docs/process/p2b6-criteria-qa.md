# P2b-6（GC）验收判据 — QA 交付（2026-10-24，待并入卡）

> 来源：QA 独立设计，manager 归档。与 architect 的"反例构造 + 金丝雀矩阵 + schema 漂移 tripwire"合并后进 P2b-6 卡。

## 1. 根集合完整性：两个方向都必须验

| 方向 | 断言 | 漏了会怎样 |
| --- | --- | --- |
| **不误删** | `F ⊇ R`：每个合法根 GC 后可读（`verify --deep` + 全路径逐字节） | 误删活数据 |
| **不漏标** | `M = R`：mark 访问到的根集合 == 合法根集合 | 多留垃圾 + 掩盖根表漂移 |

三条硬断言：

1. 每个根 `visited(r)`（防 mark 提前返回）；
2. `freed ∩ reachable = ∅`（逐对象 ID）；
3. `freed_unreachable ≠ ∅`（**非真空**：证明 GC 真动手，而不是"什么都没回收"也判 PASS）。

**正反例**（卡里必须留"根枚举可替换"的注入缝）：

- 正例 A/B（正常回收 + 全部根仍可读）；
- **反例 C**：把 snapshot 行从根表删掉但对象仍可达 → `G1`（不误删）**必红**；
- **反例 D**：mark 少给一个根 → `G2`（不漏标）**必红**；
- **反例 E**：构造确定不可达对象 → `G5`（非真空）**必红**。

**验收项（QA 建议直接写进卡）**：GC 的 `verify --deep` 必须覆盖 **snapshot 表与 workspace base**，不能只遍历
branch head——否则 `G1` 会被"只验 branch head"蒙过去。

## 2. 金丝雀矩阵（10 例）

| # | 形状 | 期望 |
| --- | --- | --- |
| K1 | branch 直引 | 保留 |
| K2 | 仅 snapshot 引用 | 保留 |
| K3 | 仅未发布 workspace 的 base 引用 | 保留 |
| K4 | 保留期内历史 commit / 期外 | 前者保留，后者允许回收（两侧各一例） |
| **K5** | 两根共享子树 | **必须保留**（两次 GC 后仍可读） |
| **K6** | 页面被多文件共享 | 删掉一个文件后仍保留 |
| K7 | 完全不可达 | 回收，之后 `verify --deep` 干净 |
| **K8** | 与 2d 接口：`pack` 行在、文件缺失 | GC **不得**删索引行"修复"，必须报 `MissingPack` |
| K9 | 死字节（并发败者帧） | 允许重打包回收，**不得**报 corrupt（KI-10） |
| K10 | 空 pack | 一律 FAIL |

K5/K6 是"共享"的核心：只验 K1/K7 的实现会在共享子树上误删。
