# P3 验收骨架（QA 设计，manager 归档）

> 来源：QA 2026-10-24（`F:/work/qa-scratch/p3-acceptance-skeleton.md` 的仓库版本）。**只分层、不落断言**；
> 正式判据等 architect 的 P3 ADR 定完四件事（见 §5）后由卡定义。

## 1. 分层按"要不要真实挂载"，不按模块

| 层 | 能在什么环境跑 | 失败信号可靠性 |
| --- | --- | --- |
| **L1 驱动无关模型** | 无驱动 / 无管理员 / CI | 高（确定性） |
| **L2 真实挂载 + 真实程序** | 需驱动与挂载点 | 中（受缓存/时序影响，必须重复 + 对照） |
| **L3 环境前置与生命周期** | 需管理员 / 需装驱动 | 高但**最容易被跳过**，必须显式计账 |

原则：**能在 L1 判的绝不下放 L2；只能在 L2 判的不要试图在 L1 模拟**——否则会造出"看起来验过"的假判据
（P2 的 C11'/K6 就是这么翻车的：判据在格式里根本不可构造）。

## 2. L1 候选（十条，各带"怎么红"）

1. 路径规范化（`..`/`.`/尾点尾空格/长路径/UNC）—— 逐条反例必须被拒绝或规范化到预期形态；
2. 大小写映射 —— case-only 改名、同名不同大小写冲突、折叠后碰撞；
3. **错误映射**（typed ↔ NTSTATUS）—— `match` 穷举，**缺一个编译不过**；
4. 打开-创建处置矩阵（Create 的 disposition × 目标是否存在 × 是否目录）—— 表驱动，**缺格即红**；
5. 共享模式矩阵（读/写/删 8 组合）—— 冲突组合必须拒绝，P2b-2e 的 `share_mode(0)` 经验可复用；
6. **delete-pending 状态机** —— 标记后新 open 被拒、最后一个 handle 关闭才真正删除、可被 cancel；
7. 目录枚举（resume/continuation、`.`/`..` 过滤、重命名中的目录）；
8. 时间戳语义（FILETIME 100ns since 1601、精度、只读性）；
9. 长度-偏移（稀疏写补零、越界写扩展）—— 与 P2 `truncate` 复活同族；
10. **FileId 跨重启稳定性**（若 ADR 要求）。

## 3. L2 候选（六条，L1 无法忠实模拟）

- SQLite（WAL + rollback journal，kill 后 `integrity_check` 干净）；
- 构建工具链（增量构建第二次不重建）；
- git（`status` clean + case-only 改名）；
- 包管理器解压（delete-on-close 与长路径）；
- 编辑器保存（临时文件 + rename，无残留）；
- Unity 资源导入；
- **驱动缓存一致性**：从底层目录改文件后，经挂载点必须**立即**读到新内容（notify 缺失只有这层能抓）。

## 4. L3 六项

- WinFsp SDK 缺失必须**编译失败并说明原因**（不得跳过编译当通过）；
- 装 → 挂 → 卸 → 再挂；盘符 / 目录 / UNC 三种挂载点；
- 管理员 vs 普通用户；
- **有句柄时卸载必须被拒绝**；
- 性能原始数据（**不与 P2 的 store 数字混比**）。

## 5. 需要 architect 在 ADR 里先定的四件事（否则"怎么红"写不出来）

1. **大小写策略**：折叠（Windows 程序假定不敏感）还是拒绝；
2. **共享模式与 delete-pending 的支持程度**：完整矩阵，还是最小子集；
3. **FileId 是否必须跨重启一致**；
4. **范围外清单**：mmap I/O、byte-range locks、symlink/reparse、ADS —— 每项都要写明**拒绝时的 NTSTATUS**。

第 4 条尤其重要：**范围外的每一格都必须有明确的拒绝语义**，否则它会在 L2 以"程序莫名失败"的形式出现，
那时分不清是 bug 还是"不支持"。

## 6. 三件跨层要求

1. **可证伪自检**：每层至少一条"故意改坏必须红"；建议变异点 = 路径规范化、case 映射、共享模式决策、delete-pending、notify 回调；
2. **重复稳定性**：L2 每条至少 3 次（单次通过可能是缓存侥幸，与 P2 的"两次 GC 后仍可读"同源）；
3. **证据边界**：按 L1/L2/L3 分别计数，"未验证"单列；**L2/L3 不得用来充 L1 的数量**。
