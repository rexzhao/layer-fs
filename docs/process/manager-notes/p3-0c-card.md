# P3-0c 任务卡（在 profile v3 落地前冻结真实 v2 旧库夹具）

> 状态：**已派**（2026-10-24）。优先级：**高于 P3-1 收尾与任何 P3-1 修复**——因为 v3 一旦落地，真实 v2 store 就再也造不出来，
> 而 P3-2 的“旧根拒绝”判据要求**真实旧库**（合成的不算）。
> 前置：P3-1 暂停（十个模块与四项修复已完成，剩余交付件可稍后）。

## 1. 为什么必须现在做

P3-2 要落 inode record v3。**v3 读取器拒绝 v2，写入路径只写 v3** ⇒ v3 生效后仓库里无法再生出真实 v2 库。
而 ADR-005 v3 草案 §8 的拒绝判据要求：**真实 v2/v1 夹具 + 被拒后字节不变 + 连续两次都拒 + fmt 自识别**。
事后合成“把 fmt 改回 1”只能测自识别，替代不了真实旧库——那会让判据变成自证。

## 2. 范围（独立分支 `p3/v2-fixtures`，基于当时 `origin/main`）

1. **用当前 v2 代码生成一个真实旧库**（不改任何产品代码）：
   - 至少一个 commit，含一个目录 + 一个文件；
   - 文件有**非零 created/modified**、大小跨一个 chunk 边界（例如 20–40 KiB，确认产生多个 chunk）；
   - 可选一个 snapshot（用于 P3-2 的 snapshot 根拒绝用例）；
   - 记录生成时的 **commit hash、命令、预期 root id、对象数**。
2. **冻结为只读夹具**：`crates/fs-snapshot/tests/fixtures/snapshot-v2-store/`（含 `store.sqlite`、`packs/`、`objects/`），
   加 `README.md`（生成步骤、预期值、**“不要重新生成”**）。
3. **测试**（只读）：
   - 用 v2 profile 打开并**逐字节**读到该文件（内容哈希与 README 一致）；
   - 目录可枚举、root id 可解析；
   - **夹具字节清单自检**：对夹具每个文件算 `(相对路径, 长度, BLAKE3)`，与 README 中的清单**逐条相等**
     （防有人不小心重建/覆盖）。
4. **只读性**：测试不得写入夹具目录；测试结束前后对夹具做 `(路径, 长度, mtime)` 清单比对，必须相同。
5. **v1 夹具**：若当前代码还能生成 P1/v1 形态，顺手冻结一份；**造不出来必须在 README 写明原因**
   （例如“v1 从未发布 / 当前写入路径只写 v2”），**空白即退回，不许伪造**。

## 3. 验收（QA）

1. 用 v2 读取器**独立**打开、逐字节读文件；自己算件数与字节清单，再与 README 对照（顺序不能反）；
2. README 的“生成命令 + commit”必须**可重现同一 root id**（commit 存在于历史；自己都重不出来则不算真实）；
3. 只读性：前后 `(路径, 长度, mtime)` 相同；
4. **判定口径**：真由 v2 代码生成 → README 有笔误也判 PASS（改文档即可）；**手工拼字节或从 v3 反推 → FAIL**。

## 4. 边界

- 只读夹具 + 测试，**不改产品代码**、不动 v3、不改 ADR；
- 分支合入后，P3-2 的“旧根拒绝”判据直接引用这些夹具，不再另造。

## 5. 交付

- 四步检查照旧（`fetch` → `rebase` → `is-ancestor` → `diff -- docs/` 为空）；
- 提交说明首行写 `判据影响：无（不改判据）`（本卡不改变任何绿红边界）；
- 回我 SHA + README 里的关键数字（root id、对象数、夹具总字节）。
