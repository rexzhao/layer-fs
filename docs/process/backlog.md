# 后续事项登记（Backlog）

> 规则：**只登记、不静默继承**。每项必须有：来源、为什么当时没做、重新拾起的触发条件、验收要点。
> 任何阶段收口时把新增项写进这里；后续阶段开始前先读这一份。

## B-1 Seal / Compact（规格 §2 Phase 2 第 5、10 条的后台部分）

- **来源**：spec P2 §2；ADR-007 §6（Seal）；ADR-008 §6.2 的"显式未完成项"。
- **为什么没做**：owner 2026-10-24 决定 P2b 按现状收口，Seal 不在 P2 内。
- **现状**：GC 侧已为它准备好全部护栏——`RootKind::SealedContent` 存在、`ov_inode.sealed_content` 列尚未存在、
  T1 全列清单 / T2 注册表 / §27.D K 矩阵把 `SealedContent` 列为**唯一允许的 pending 项**。
- **卡已写**：`docs/process/seal-card.md`（§1 三处 tripwire 红→修→绿、§2 根不一定是树、§8 四项实现前定死、
  §9 十五步实现顺序、§10 两处规格裁定 S1 / verify 不扩 / 生命周期 / `for_objects` / 空编码）。
- **触发条件**：进入"封存/压缩"相关工作，或需要在 P3 之前补齐 P2 规格项。
- **验收要点**：Seal 卡的 15 步；S1（overlay 引用面只能由 `sealed_content` 表达）；闭包完整性构造判据。

## B-2 K5c 的逐字节版本

- **来源**：P2b-6 合并报告 §5 缺口 3。
- **为什么没做**：需要"只损坏某一棵树"的可控注入面（否则删 pack 会让所有根都不可读，"逐字节比对"退化）。
- **触发条件**：需要更强证据证明"GC 不动幸存根的任何字节"时；或引入按树粒度的损坏注入 seam 时。
- **验收要点**：损坏一棵树后，另一棵树的每个对象逐字节相同；`freed` 不含另一棵树的任何 oid。

## B-3 三条 R 升 Y（Y4、Y18、Y19）

- **来源**：P2b-6 QA 判定（R=3）。
- **为什么没做**：各需 30–40 行夹具（`stage_pack_with_dead_frame` + 手工 inode 表；半存活 pack 形状）。
- **触发条件**：GC 相关代码再次改动时（这些判据最容易随改动失效）；或需要把 GC 证据升到"全部独立复现"时。
- **验收要点**：Y4 反向断言（`freed_objects==0 && packs_repacked==1 && reclaimed_dead_bytes>0`）；
  Y18/Y19 的 repack 两点各自的到达点号与重开不变量。

## B-4 `verify --deep` 覆盖 overlay 根

- **来源**：P2b-6 期间 ADR-008 §6.2 的裁定（不扩，且"不得静默宣称"）。
- **为什么没做**：会改变 `fs-cli verify --deep` 在活跃 store 上的**可观察行为**（有活 overlay 时得到 typed 错误/等待）。
- **触发条件**：需要 CLI 级"全根"体检时；应另开卡并显式命名开关（如 `--include-overlays`）。
- **验收要点**：默认行为不变；显式开关时覆盖 `pending_root`/`sealed_content`；有活 overlay 时错误类型明确。

## B-5 Y21b（GC 窗口内并发写）

- **来源**：P2b-6 观察窗口（窗口 <1 ms，无法稳定采样）。
- **触发条件**：需要证明"GC 期间其他写者得到 typed `Busy`"时有可复现的拉长窗口手段（大 store 或注入停点）。
- **验收要点**：报告窗口时长/采样方式/占比；`M=0` 时写"未验证"，不得写"通过"。

## B-6 J1 内存次线性

- **来源**：spec §5 第 4 条（「不把全量对象索引常驻内存当作正确性前提」）与 ADR-008 §2 的 **P8**（mark 用临时 SQLite 存标记集）；P2b-6 未测。
- **为什么没做**：RSS 受分配器影响，单次测量不足以判据。
- **触发条件**：需要在百万级对象上验证 mark 的常驻内存时。
- **验收要点**：两规模峰值 RSS 的比值与原始数值；若做成判据，先固定分配器与测量方式。

## B-7 两项已知优化（KI-4、KI-8）

- **KI-4**：快照编码器输入驻留 O(N)，ADR-005 §8 要求 O(N/64)。
- **KI-8**：物化器未复用 base 的目录树 oid 与 extent（同树无变更再发布 ≈1.4× P2a）。
- **触发条件**：大库（>10⁵ 对象）或再发布成本成为瓶颈时。
- **验收要点**：峰值内存曲线 / 再发布耗时与 P2a 对照，附原始数据。

## B-8 SUPERSEDE 后旧句柄的读（跨 GC 的联合用例）

- **来源**：QA 在 P3-2 预审中发现 ADR-009 内部矛盾（`:117` 删旧 inode ↔ `:239` "核心不存在该状态"）；裁决后
  ADR-009 §4.2 定为「旧 inode 记录保留（只增）」，可读性由「GC 期无句柄」保证（ADR-008 §6.1）。
- **为什么没做**：这条联合用例需要 **adapter 句柄表**（P3-3）+ **GC 可被调用**，G1/G2 里两样都没有。
- **触发条件**：P3-3 adapter 挂载可跑真句柄时，作为该卡的必做验收项。
- **用例**：`open(handle) → SUPERSEDE 同路径 → gc(roots) → read(handle)`，期望**读成功且内容与打开时一致**。
- **验收要点**：没有它，“由句柄表保证有效”只是一句声明；同时核对 GC 之后（无句柄）不应再有可读路径。

## B-9 只读挂载期间 GC 必须**拒绝**（不是“跑完零改动”）

- **来源**：QA 核出“GC 期无句柄”的承重件是 **overlay 的 `locking_mode=EXCLUSIVE`**（`fs-overlay/src/schema.rs:76`），
  不是 `store.sqlite` 的锁（WAL 下读者与维护者可以共存）。`workspace_open` 是**急打开** overlay（`repo.rs:517`）并
  紧接 `pending_root()` 查询（`repo.rs:525`）——即首次加锁，因此返回时已排他持有。
- **为什么没做**：属 P2b-6 的追补（不需要 adapter、不需要 SDK），排在 P3-2 G1 之后。
- **用例**：进程 A `Repo::open` + `workspace_open` + 真读一次（证明持有者活着）⇒ 进程 B `gc --dry-run` 必须**失败**、
  消息含 `in use`、**且不得打印计划**；A 释放后 `gc --dry-run` 必须成功（阴性对照）。
- **验收要点（决定这条用例存在的东西）**：**“什么都没改”与“拒绝了”在 `--dry-run` 下输出可能一样**。若只读路径某天
  改成“不打开 overlay”（性能优化 / 缓存命中），锁就不在了，GC 会在活句柄旁开扫，而**报告仍然正常**——这类
  “前提消失、输出不变”的退化只有这条断言能抓。红法：删 `locking_mode=EXCLUSIVE` / 只读路径不再打开 overlay /
  把拒绝改成“打计划零改动”。

## B-10 overlay 不可达 inode 行（SUPERSEDE 保留）的回收

- **来源**：ADR-009 §4.2「SUPERSEDE 造出的保留状态」裁决为 **B（只增保留）**；泄漏的是**行/页**，不是内容副本
  （base 内容由历史根引用；overlay 页是替换前已有的那一行，不是复制）。
- **触发条件**：挂载期反复“SUPERSEDE 命中仍有打开句柄”导致 overlay 不可达行累积（66–90 B/条），直到 `workspace_discard`。
- **方案 C（推荐）**：**离线 GC 在 overlay 排他锁下**扫描并删除不可达 inode 行——比方案 A（adapter 在最后一个旧句柄
  关闭时 release：需保留标记 + release API + 崩溃后清扫三点）少两个机制，且顺手解决 overlay 的一般性垃圾。
- **验收要点**：① 验收前提**必须**写明“overlay 排他锁”（否则重蹈“以为 store 独占就够”的覆辙）；② 扫描前后**可达行
  集合不变、根可读**；③ 若将来实现在线 GC 或与只读挂载并存，根集必须增加 **live-handle 输入**（ADR-008 §6.1）。

## B-11 ACL 强制（SD 语义）

- **来源**：`ADR-005` 草案 §5（安全描述符）与 **§10 第 3 条**（SD 语义未启用：P3 只存 0，`SetSecurity` 拒绝）承诺「ACL 强制留 backlog」；ADR-009 **W10** 定义
  "ACL 读默认 SD、写拒绝"。
- **为什么没做**：P3 的目标是"能挂载、能读写、语义不静默错"，ACL 强制属于安全面，不影响文件语义正确性；且需要
  与 Windows 安全描述符的继承/继承标记一并设计。
- **触发条件**：需要真实权限隔离（多用户/服务账号）时；或 L2 实测发现拒绝行为与 NTFS 不一致时。
- **验收要点**：`SetSecurity` 从"拒绝"变为"应用"时必须同时给出**继承**（`SE_DACL_AUTO_INHERITED`）与**拒绝优先**的判据；
  在此之前草案 §10 第 3 条的“只存 0”必须保持，不得出现"存了但不生效"的中间态。

## B-12 `waited_ms` 的钟起点（CAS 路径包含调用前的工作）

- **来源**：P3-2 G1 期间 `failed=1` 复现定位——`waited_ms = 5794` 而包住它的 `commit` 调用只有 `5631` ms；
  `busy::start()` 只在 `MainDb::lock()` 里重启（`main_db.rs`），CAS 路径读同一个钟 ⇒ 报的是“自上次主库加锁以来”，
  包含调用**之前**的物化时间。
- **为什么没做**：修它要动产品（钟的语义），且会让现有断言的余量口径变化；当时 G1 只需把它记成**观测**。
- **触发条件**：需要“报给调用方的等待时间就是本次等待”时。
- **做法**：CAS 发布路径开始处也调一次 `busy::start()`；随后**上界才成为真不变量**：`waited_ms <= measured`
  （内层量不可能大于包住它的量）。
- **验收要点**：① `waited_ms <= measured` 在大 payload（16/32 MB）下仍成立；② 主库路径语义不变（原有 `waited_ms >= policy` 仍在）；
  ③ `busy.rs` 头注释改回“本次操作的等待”。
- **当前状态（该用例）**：**观测**——只断言 `waited_ms >= MAIN_BUSY_TIMEOUT_MS`（超时 ⇒ 等待 ≥ 超时）；
  上界等本卡。历史三条经验性上界（`±100`、`policy + 1000`、`>= measured`）已删，理由见
  `docs/process/criteria-and-acceptance.md` §九。

## B-13 `doc_refs` 检查（引用 ⇒ 小节必须存在）落成一个 `#[test]`

- **来源**：P3-2 期间 QA 的脚本 `check_adr_refs.py` 在 main 上抓出两条悬空引用与一条“节存在、内容不对”。
- **为什么没做**：它属仓库卫生，不属任何功能卡；当时先用手工与 QA 脚本顶住。
- **做法**：`crates/fs-cli/tests/doc_refs.rs`（**一个** `#[test]`，不配 CI 副本——两份必然漂移）。规则：只扫正文
  （遇「修订记录/变更记录/修订历史」节即停）/ 编号带不带点都认（`## 8.` 与 `## 8 `）/ 失败时打印该 ADR 的实际小节清单
  （区分“没有这一节”与“正则写错”）。
- **验收要点**：阳性对照（往正文塞一条不存在的引用 ⇒ 红）/ 阴性对照（同一句放进「修订记录」节 ⇒ 绿，证明豁免没把判据改瞎）/
  扫 `docs/process` + `docs/reports` + `docs/adr` 三目录（基线 0）。

## B-14 W2（一个 workspace 同时只有一个打开者）目前没有判据

- **来源**：ADR-009 §1 的 W2 边界（2026-10-25 由 QA 用 350 ms 锁探针坐实机制），但**没有测试**直接断言它。
- **为什么没做**：当时把它当“叙述性事实”；P3-2 G2 的 `remove_at(parent, name, expected_id)` 让它变成**承重前提**
  ——定位键由 adapter 维护，前提正是“改名只能由本进程发起”。
- **触发条件（拆两条，别捆在一起）**：
  - **B-14a（现在做，约 2 行）**：同一进程内 `workspace_open` 同名两次 ⇒ 第二次得到 typed `WorkspaceInUse`。
    这是最可能出现的违反形态，且是 `remove_at` 定位键**最直接**的承重前提。
  - **B-14b（缓做）**：跨进程（CLI 顶掉 CLI）。要起真进程、成本更高、也更可能因环境差异不稳。
- **验收要点**：断言**错误类型**而不是“失败”；另记一条：若将来支持并发只读，本卡与 `remove_at` 的定位键**同时失效**（ADR-009 W3 修订里那句）。
