# 后续事项登记（Backlog）

> 规则：**只登记、不静默继承**。每项必须有：来源、为什么当时没做、重新拾起的触发条件、验收要点。
> 任何阶段收口时把新增项写进这里；后续阶段开始前先读这一份。

## B-1 Seal / Compact（规格 §2 Phase 2 第 5、10 条的后台部分）

- **来源**：spec P2 §2；ADR-007 §6（Seal）；ADR-008 §6.2 的"显式未完成项"。
- **为什么没做**：owner 2026-10-24 决定 P2b 按现状收口，Seal 不在 P2 内。
- **现状**：GC 侧已为它准备好全部护栏——`RootKind::SealedContent` 存在、`ov_inode.sealed_content` 列尚未存在、
  T1 全列清单 / T2 注册表 / §27.D K 矩阵把 `SealedContent` 列为**唯一允许的 pending 项**。
- **卡已写**：`docs/process/seal-card.md`（§1 三处 tripwire 红→修→绿、§2 根不一定是树、§8 四项实现前定死、
  §9 十五步实现顺序、§10 两处规格裁定 S1 / verify 不扩 / 生命周期 / `for_objects` / 空编码）。
- **触发条件**：进入"封存/压缩"相关工作，或需要在 P3 之前补齐 P2 规格项。
- **验收要点**：Seal 卡的 15 步；S1（overlay 引用面只能由 `sealed_content` 表达）；闭包完整性构造判据。

## B-2 K5c 的逐字节版本

- **来源**：P2b-6 合并报告 §5 缺口 3。
- **为什么没做**：需要"只损坏某一棵树"的可控注入面（否则删 pack 会让所有根都不可读，"逐字节比对"退化）。
- **触发条件**：需要更强证据证明"GC 不动幸存根的任何字节"时；或引入按树粒度的损坏注入 seam 时。
- **验收要点**：损坏一棵树后，另一棵树的每个对象逐字节相同；`freed` 不含另一棵树的任何 oid。

## B-3 三条 R 升 Y（Y4、Y18、Y19）

- **来源**：P2b-6 QA 判定（R=3）。
- **为什么没做**：各需 30–40 行夹具（`stage_pack_with_dead_frame` + 手工 inode 表；半存活 pack 形状）。
- **触发条件**：GC 相关代码再次改动时（这些判据最容易随改动失效）；或需要把 GC 证据升到"全部独立复现"时。
- **验收要点**：Y4 反向断言（`freed_objects==0 && packs_repacked==1 && reclaimed_dead_bytes>0`）；
  Y18/Y19 的 repack 两点各自的到达点号与重开不变量。

## B-4 `verify --deep` 覆盖 overlay 根

- **来源**：P2b-6 期间 ADR-008 §6.2 的裁定（不扩，且"不得静默宣称"）。
- **为什么没做**：会改变 `fs-cli verify --deep` 在活跃 store 上的**可观察行为**（有活 overlay 时得到 typed 错误/等待）。
- **触发条件**：需要 CLI 级"全根"体检时；应另开卡并显式命名开关（如 `--include-overlays`）。
- **验收要点**：默认行为不变；显式开关时覆盖 `pending_root`/`sealed_content`；有活 overlay 时错误类型明确。

## B-5 Y21b（GC 窗口内并发写）

- **来源**：P2b-6 观察窗口（窗口 <1 ms，无法稳定采样）。
- **触发条件**：需要证明"GC 期间其他写者得到 typed `Busy`"时有可复现的拉长窗口手段（大 store 或注入停点）。
- **验收要点**：报告窗口时长/采样方式/占比；`M=0` 时写"未验证"，不得写"通过"。

## B-6 J1 内存次线性

- **来源**：ADR-008 §5.4 的内存判据；P2b-6 未测。
- **为什么没做**：RSS 受分配器影响，单次测量不足以判据。
- **触发条件**：需要在百万级对象上验证 mark 的常驻内存时。
- **验收要点**：两规模峰值 RSS 的比值与原始数值；若做成判据，先固定分配器与测量方式。

## B-7 两项已知优化（KI-4、KI-8）

- **KI-4**：快照编码器输入驻留 O(N)，ADR-005 §8 要求 O(N/64)。
- **KI-8**：物化器未复用 base 的目录树 oid 与 extent（同树无变更再发布 ≈1.4× P2a）。
- **触发条件**：大库（>10⁵ 对象）或再发布成本成为瓶颈时。
- **验收要点**：峰值内存曲线 / 再发布耗时与 P2a 对照，附原始数据。
